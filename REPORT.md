# Материалы отчёта по производственной практике

**Тема:** разработка модуля «Личный кабинет пользователя» с авторизацией и CRUD-операциями.

**Контекст:** внутренний портал для администраторов сети кофеен «Кофеин», разработанный в рамках учебного задания веб-студии «Астра».

## Цель и результат

Разработано классическое серверное веб-приложение, в котором пользователь регистрируется, входит в личный кабинет и управляет собственным списком поставщиков. Реализованы создание, просмотр, изменение и удаление записей. Для поиска использовано асинхронное обращение к серверу через Fetch API.

Стек: PHP, MySQL, PDO, HTML5, Bootstrap 5.3.3, собственные CSS Grid/Flexbox и JavaScript. Выбран чистый PHP без дополнительных фреймворков, чтобы исходный код было удобно изучать и запускать локально.

## Архитектура

Браузер отправляет запрос контроллеру public/index.php. Контроллер проверяет сессию, метод запроса, CSRF-токен и входные данные. Запросы к MySQL выполняются через PDO. Для HTML-страниц используется app/view.php. Маршрут /api/suppliers возвращает JSON для поиска. Конфигурация и SQL находятся за пределами публичной папки.

```text
Браузер (HTML / Bootstrap / JavaScript)
                 │ HTTP GET / POST / Fetch
                 ▼
public/index.php — маршруты, сессия, права, валидация
       │                              │
       ▼                              ▼
app/view.php                 app/bootstrap.php → PDO → MySQL
HTML-ответ                                  users, suppliers
```

## База данных

Используется кодировка utf8mb4 и InnoDB. Пользователь может иметь любое количество поставщиков. Каждый поставщик принадлежит ровно одному пользователю.

```text
users                              suppliers
──────────────────────             ──────────────────────
PK id INT UNSIGNED          1 ── N PK id INT UNSIGNED
   name VARCHAR(100)                  name VARCHAR(150)
UQ email VARCHAR(254)                 contact_person VARCHAR(100) NULL
   password VARCHAR(255)             phone VARCHAR(30) NULL
   created_at TIMESTAMP           FK user_id INT UNSIGNED
                                     created_at TIMESTAMP
```

| Таблица/поле | Назначение и ограничения |
|---|---|
| users.id | Первичный ключ, автоинкремент |
| users.name | Имя пользователя, обязательно, до 100 символов |
| users.email | Уникальный email; нормализуется к нижнему регистру |
| users.password | Хеш пароля; открытый пароль не сохраняется |
| suppliers.id | Первичный ключ, автоинкремент |
| suppliers.name | Название компании, обязательно, до 150 символов |
| suppliers.contact_person | Контактное лицо, необязательно, до 100 символов |
| suppliers.phone | Телефон, необязательно, 5–30 допустимых символов при заполнении |
| suppliers.user_id | Внешний ключ users.id и индекс для выборки записей владельца |
| created_at | Дата создания записи, устанавливается базой автоматически |

При удалении пользователя непосредственно из базы его поставщики удаляются каскадно (ON DELETE CASCADE). Интерфейс удаления аккаунта не входит в задание. Дубли названий поставщиков допустимы: разные записи могут иметь разные контакты.

## Основные фрагменты исходного кода

### Подготовленные запросы (app/bootstrap.php)

```php
function query(string $sql, array $parameters = []): PDOStatement
{
    $statement = db()->prepare($sql);
    $statement->execute($parameters);
    return $statement;
}
```

Параметры передаются отдельно от текста SQL. Эмуляция подготовленных выражений отключена. Ввод пользователя не используется для формирования имён таблиц или SQL-операторов.

### Регистрация и хеширование (public/index.php)

```php
query('INSERT INTO users (name, email, password) VALUES (?, ?, ?)',
    [$data['name'], $data['email'], password_hash($password, PASSWORD_DEFAULT)]);
```

Перед записью проверяются имя, email и длина пароля. Уникальный индекс email защищает от дублирования даже при одновременных запросах. При повторном email пользователь получает понятную ошибку.

### Вход и сессия (public/index.php)

```php
if ($account && password_verify($password, $account['password'])) {
    session_regenerate_id(true);
    $_SESSION['user_id'] = $account['id'];
    $_SESSION['csrf'] = bin2hex(random_bytes(32));
    redirect('/dashboard');
}
```

Пароль сверяется с хешем функцией password_verify. После входа меняется идентификатор сессии. Cookie имеет HttpOnly и SameSite=Lax; при HTTPS включается Secure. Неавторизованный посетитель защищённых страниц перенаправляется на /login.

### Разграничение прав (public/index.php)

```php
query('SELECT * FROM suppliers WHERE id = ? AND user_id = ?', [$id, $user['id']]);
query('DELETE FROM suppliers WHERE id = ? AND user_id = ?', [$id, $user['id']]);
```

Условие user_id применяется в списке, поиске, загрузке формы, обновлении и удалении. Идентификатор владельца берётся только из серверной сессии. Подмена id в адресе не открывает доступ к чужой записи: возвращается 404.

### Защита формы

```php
hash_equals($_SESSION['csrf'], $_POST['csrf'])
```

Для каждого POST проверяется случайный токен, связанный с сессией; в контроллере перед сравнением проверяется тип входного значения. Удаление и выход недоступны через GET. Пользовательские строки в HTML проходят htmlspecialchars, а результаты Fetch вставляются через textContent, чтобы ввод не выполнялся как HTML/JavaScript.

### JavaScript и интерфейс

```javascript
if (form.matches('[data-confirm]') && !window.confirm('Точно удалить поставщика?')) {
  event.preventDefault();
}
```

Поиск отправляет GET-запрос на /api/suppliers?q=... через fetch и обновляет таблицу. Предыдущий поисковый запрос отменяется через AbortController. Валидация браузера и JavaScript дополняет серверную проверку. Сервер остаётся источником проверки, даже если клиентские проверки отключены.

## Адаптивность и сценарий демонстрации

Шапка переносит элементы с помощью Flexbox, карточки кабинета расположены CSS Grid. При уменьшении ширины карточки складываются в одну колонку, таблица получает горизонтальную прокрутку. Формы содержат связанные label, сообщения ошибок и индикатор результатов поиска.

1. Открыть /register и создать аккаунт.
2. Показать ошибку короткого пароля или неверного email.
3. Войти и показать имя пользователя в кабинете.
4. Добавить две компании, например «Обжарочная Север» и «Молочная ферма».
5. Изменить телефон первой компании, выполнить поиск.
6. Нажать удаление, сначала отменить, затем подтвердить.
7. В другом браузере создать второго пользователя и показать пустой список.
8. Попытаться открыть id первой компании вторым пользователем: доступ отсутствует.
9. Выйти и открыть /dashboard: переход на /login.

## Иллюстрации для отчёта

Не показывайте пароли и config.php. В этот материал не включены вымышленные скриншоты или утверждения о проведённых пользователем испытаниях.
